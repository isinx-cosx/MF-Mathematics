# 设置备份（导出 / 导入）

> 🚩 **已退役（2026-10-07）**：本文的实现表讲的是**已废弃的 .NET 宿主**（`WindowBridge.cs` 等）。
> **现役 Rust 侧的对应内容见 [`docs/link/FEATURES.md`](link/FEATURES.md) §4** ——
> 含 `Store*` 契约、包里有什么、导入的两条性质，以及一条残留：**`.bak` 里可能有明文 AI 密钥**。
>
> **本文暂不删除**：仓库里还有多处引用它（清单见
> [`docs/PROJECT-BOARD.md`](PROJECT-BOARD.md) §3 R8），等引用改完再删。
> **引用本文任何一处数字前，请先核对 `FEATURES.md`。**

> 落地于本轮。用途是**换机迁移**：把设置与外观偏好搬到另一台机器。
> 本文的重点不是"能导出"，而是**凭据不进备份、导入也不清凭据** —— 写错的话用户会静默失去
> API Key 或登录状态，而且很难查。

## 1. 包里有什么、没有什么

| 进备份 | 不进备份 |
| --- | --- |
| 设置文件：历史、工作区、会话记录、教程进度、更新偏好等（`%LOCALAPPDATA%\MFMath\settings\*.json`） | **`ai.json`**（AI 的 API Key，DPAPI 密文） |
| 外观偏好：`localStorage` 里 `mf_` 前缀的键（主题/形状/密度/字体/跟随系统） | **`account.json`**（登录 token 密文） |
| 包元数据：`app` / `kind` / `version` / `exportedAt` / `appVersion` / `excluded` / `stripped` | **`search.json`**（Wolfram App ID 密文） |

两道防线，都是**可见的**（写进包里，不是悄悄处理）：

1. **整份排除**上面那三个文件，并把它们列在 `excluded` 里；
2. 对其余文件再做一次**字段级剥离**：字段名命中 `protected / password / secret / token / apikey`
   就不写入，并把剥掉的字段名记进 `stripped`。

为什么密钥干脆不带：DPAPI 密文换台机器也解不开，搬过去只是一串没用的字节，
却会让人误以为"密钥跟着走了"。**换机时密钥应当在新机器上重新填一次。**

## 2. 导入的两条性质（有断言守着）

1. **不会清掉你现在的凭据**：导入只写包里存在的文件，而那三个凭据文件**永远不写** ——
   即便有人手改备份、把 `ai.json` 塞进去，也会被跳过并报告（`skipped`）。
2. **坏包一律拒绝，且不部分写入**：`app` / `kind` / `version` 任一不对就整包拒绝并给可读原因
   （"这不是 MF-Mathematics 的设置备份"、"备份来自更新的版本（v99）；请先更新软件再导入"）。
   拒绝发生在写第一个文件之前，所以磁盘状态不变。

生效时机：**设置文件与外观偏好都在启动时读取**，所以界面如实说"重启后全部生效"，
不假装即时生效（否则用户会以为导入没成功）。

## 5. 边界

- **不做云同步**：备份是本地文件，用户自己保管（要不要上云是产品决策，见 `OPEN-ITEMS.md` §6）。
- **不做增量/合并**：导入是"覆盖同名文件"的语义，界面上先确认再执行。
- **教程进度**在 `mf_` 前缀之外的部分（如示例库的本地标记）若将来改用别的键名，
  需要同步 `collectPrefs()` 的前缀规则 —— 现在收的是所有 `mf_` 开头的键。
