# 更新链（只提示 + 显示校验值 + 交给浏览器）

> 落地于本轮。**软件不自动下载、更不执行安装包** —— 这是你在决策里定的形态，也是本文的全部前提。

## 1. 形态：三条边界

| 做 | 不做 |
| --- | --- |
| 查站点版本、与本机版本比较 | ❌ 自动下载安装包 |
| 显示 `sha256` / 大小 / 版本差异 | ❌ 自动运行安装包 |
| 把下载页交给系统浏览器（`http/https`） | ❌ 自己实现下载器或静默安装 |

理由：自动执行安装包等于给自己装一条"下载并运行可执行文件"的通路。少一个通路少一片攻击面，
而用户点一下浏览器的代价极小 —— 而且他能在浏览器里看清下载的是什么。

## 2. 一个必须处理的真实陷阱：站点版本比本机**旧**

站点 `/api/version` 现在报的是 **1.2.0**（v1 的版本），而 v2 应用声明的是 **2.0.0**。
如果按"版本不同就算有新版"，v2 用户会被提示"有新版本 1.2.0"，然后被引去下载 **v1 安装包** ——
那是降级。所以比较的是**关系**：

| relation | 界面 | 说明 |
| --- | --- | --- |
| `newer` | 顶栏出现「有新版本」徽标 + 结果行写明差异 + 下载入口 | 只有这一种才叫"有更新" |
| `same` | 「已是最新版本」 | — |
| `older` | 「站点上的版本（1.2.0）比本机旧」+ 原因 | **不提示下载**；并提示发布 v2.0 时要把站点 `src/lib/constants.ts` 的 `VERSION` 改成 2.0.0 |

版本比较在 `UpdateBridge.CompareVersions`：逐段比数字（`1.10.0 > 1.9.9` —— 字符串比较会搞错这个），
带预发布后缀的（`2.0.0-beta`）小于同号正式版。自检里有这两类样例。

## 3. 站点侧：`/api/version` 补 sha256

```json
{"code":0,"data":{"latest":"1.2.0","date":"2026-07-21","download_url":"/download",
                  "changelog":"/changelog",
                  "sha256":"1e9527be…","size":139467557},"msg":"success"}
```

- 安装包在场时按 **(路径 + 大小 + mtime)** 缓存校验值：文件一变就重算，不写死（写死的值迟早是错的，
  而"校验值错了"比"没有校验值"更糟 —— 用户会以为校验过）。
- 安装包不在场时返回 `"sha256": null` + **`sha256_reason`**（例如"服务器上还没有安装包文件"），
  界面原样显示这个理由，**不编一个值、也不留空白**。

## 4. 软件侧结构

| 文件 | 职责 |
| --- | --- |
| `MFMath.Host/UpdateBridge.cs` | `Info` / `Check` / `ResolveDownloadUrl` / `PreviewDownloadUrl` / `OpenDownloadPage` / `SelfCheck`；版本比较与信封解析 |
| `MFMath.Host/ShellOpen.cs` | 打开链接的**唯一实现**（搜索的"打开结果"与更新的"打开下载页"共用，闸门只有一份） |
| `src/lib/update/bridge.js` | 状态、偏好（`sys` 存储：自动检查 / 间隔 / 上次检查）、检查与预览 |
| `src/components/settings/UpdateGroup.vue` | 设置 → 更新：当前版本 / 通道 / 更新源 / 自动检查 / 间隔 / 手动检查 / 自检 |
| `src/App.vue` | 顶栏「有新版本」徽标（只在 `hasUpdate` 时出现） |
| `MFMath.Host/MFMath.Host.csproj` | `<Version>2.0.0</Version>`（必须显式声明，靠默认的 1.0.0.0 会永远判错） |

两条刻意的设计：

- **更新源 = 账号里的站点地址**（一处真相）。不设第二个地址框，免得两处不一致；
  要改地址去「设置 → 账号」。
- **自动检查默认关**：启动就联网是替用户做决定（也会暴露 IP 与使用时间）。开了也只在超过间隔时查一次。

## 5. 两个被用例逼出来的 bug（都值得记下）

**① 拼写错误被伪装成"桥不通"**：`ParseVersionBody` 少了一个收尾 `}`，返回的 JSON 不合法；
页面侧 `parse()` 失败返回 `null`，而调用方把它读成"宿主没有响应"。查了半天才发现是 JSON 少括号。
修法：补上 `}`；并让 `parse()` 在失败时 `console.warn` 出原文片段（诊断包会带走 console）。
教训：**"桥不通"这类结论必须有证据**，我第一版直接写死了那句文案，差点把我引向错误方向。

**② 协议闸门被"相对路径"绕开**（安全）：`OpenDownloadPage` 原本把"不是 http(s) 开头"的一律当相对路径
拼到站点地址上，于是 `javascript:alert(1)` 被拼成 `http://站点/javascript:alert(1)` —— 它已经是个
合法的 http URL，闸门形同虚设（测试里真的调用了 `Process.Start`）。
修法：带协议的（`^scheme:`）直接过闸门；不带协议的才当站内相对路径，并拒绝 `//host`、`..`、`\`、`:`、空白。
判断抽成 `LooksRelativeSafe` 并在自检里单测 —— **能单独验的逻辑才敢说它是对的**。

顺带加了一个 `PreviewDownloadUrl`（只算地址、不打开）：界面因此能在点击前显示"将打开：…"，
测试也不必真弹浏览器。

## 7. 仍未做

- **发布 v2.0 时要把站点 `src/lib/constants.ts` 的 `VERSION` 改成 `2.0.0`**（否则本机会一直显示
  "站点上的版本比本机旧"）。这是站点数据，不是代码缺陷 —— 但忘了他就不会提示更新。
- 更新**回滚**、增量更新、静默安装：明确推迟（见 `OPEN-ITEMS.md` §5）。
- 站点侧仍是"一个安装包一个地址"，没有通道（beta）与历史版本列表。
