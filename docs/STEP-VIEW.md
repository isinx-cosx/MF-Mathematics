# 分步显示（渲染层）

> 落地于本轮。前置是**工具调用**（`docs/AI-ASSISTANT.md` §4.1）：AI 只能通过 `engine_call` 拿数值。

## 1. 步骤从哪来（这是本文最要紧的一句）

**步骤 = 这一轮里 AI 调引擎的记录**，不是模型写出来的推导。

为什么必须这样：引擎信封里**没有 `steps` 字段**（已核对 `api.cpp` 与全部 `*_api.cpp`），
所以"从引擎直接拿步骤"做不到；而让模型自己编步骤就等于伪造推导 —— 那会直接违反本项目
"计算由 C++ 引擎完成"的硬约束。工具调用正好给出了那个缺失的事实来源：
**模型提出要算什么，数值由引擎给出**，于是"每一步"天然是可核对的。

界面上因此有两种呈现，内容同一份：

| 位置 | 形态 | 用途 |
| --- | --- | --- |
| AI 面板里的工具块 | 紧凑（引擎徽标 + 函数名 + 参数 + 结果 + 耗时） | 边聊边看"它算了什么" |
| 「查看步骤」→ StepViewer | **编号步骤**（第 N 步 · 函数 · 参数 · **完整结果** · 状态） | 想按步骤核对时展开看 |

两条显示纪律：
- **完整结果**：工具块给模型的内容是截断到 3000 字符的，StepViewer 给人看的是**完整值**；
- **失败保留**：失败的那一步标红并留在列表里（不隐藏、不假装成功）—— 宁可看到"这步没算出来"。

## 2. 两条入口

1. **AI 面板**：任何带引擎步骤的回答，下面都有「查看步骤（N）」按钮 → 打开 StepViewer。
2. **计算页的结果对话框**：「查看步骤」按钮 —— 它此前是个**死按钮**（`emit("steps")` 有人接，
   但接的人只往状态栏打了一行"步骤推导未接入"）。现在它真的做事：
   把这道题（表达式 + 模式 + 引擎函数）交给 AI 分步讲解，并带 `autoSteps` 让面板在收尾后
   **自动弹出步骤视图**。用户点的是"查看步骤"，所以不必再点一次发送。

通路（用 ref 而非事件总线，只有一处消费，取一次即清）：
`CalcView.onSteps()` → `requestAiTurn(prompt, {autoSteps:true})` → `App` 观察到 `aiRequest`
打开抽屉 → `AiPanel` 取走请求并自动发送 → 收尾后 `aiStepsFor` 被填 → StepViewer 自动打开。

## 3. 教程引导

`step_viewer.content` 这个目标从 v1 起就在教程里引用（设置/结果对话框的引导步骤），此前一直在
`PENDING` 里写着"分步显示尚未实现"。现在 `StepViewer` 的内容区挂上了同名 `data-tour`，
于是它从待实现清单里**删掉**了：构建自检从"已实现 29 / 待实现 2"变成 **30 / 1**
（只剩 AI 加速按钮）。它的提示也改成真实前置条件："先点结果对话框或 AI 回答里的「查看步骤」"。

## 4. 验证

| 用例 | 断言 | 结果 |
| --- | --- | --- |
| `cdp-ai.mjs` ②d/②e/②f | 「查看步骤」按钮存在；打开后 `step_viewer.content` **能定位到可见内容**；步骤被编号列出；写着引擎函数名与参数；**结果是引擎的值**（`["2","-2"]`，不是模型那句"99"）；标出"引擎已算出"；下面是 AI 的说明（措辞与数值分开）；关闭后消失；**由别处发起**：请求打开面板 + 预填 + 自动发出 + 收尾后自动弹出步骤；**计算页结果对话框的「查看步骤」不再是死按钮**（请 AI 分步讲解并带上题目，随后自动弹步骤） | 合计 **127 / 0** |

## 5. 仍未做 / 有意的边界

- **不显示"纯引擎计算"的步骤**：不给 AI 的时候，引擎只给结果、不给推导，硬凑步骤就是编。
  想按步骤看，就走「查看步骤」让 AI 调引擎。
- **步骤的顺序与分合由模型决定**：项目只保证"每个数值都来自引擎"，不保证"这一定是最优的拆解方式"。
  这是"分步显示"与"自动证明"的区别 —— 后者没做，也不在计划里。
- AI 加速按钮（`calc_block.ai_accel_button`）仍没做：那是 v1 每个计算块上的独立入口，
  与分步显示无关（见 `OPEN-ITEMS.md` §4）。
