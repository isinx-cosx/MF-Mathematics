# 明确不做 · 推迟 · 能力边界

> **本文只回答一个问题：哪些事是"我们想过、并且决定不做"的。**
>
> 目的不是免责，是**省时间**：让下一个人不用重新发现一遍"这里为什么是空的"，
> 也不用把一个刻意的选择当成待修的 bug。

**核对时间**：2026-10-07

---

## 0. 三种"没做"必须分清

混在一起看，这份清单就会退化成一张免责声明。**它们的性质完全不同**：

| 类别 | 含义 | 谁能否决 | 在哪一节 |
| --- | --- | --- | --- |
| **明确不做** | 想过，**决定不做**，有理由 | 需要新证据才能推翻 | §1 |
| **推迟** | 想做，**现在不做**，有前置条件 | 前置条件满足就做 | §2 |
| **能力边界** | **设计选择的直接后果**，不是"没做" | 改设计才能改，不是"补个功能" | §3 |
| **已知未优化** | 能用，但**慢** | 有人愿意优化就优化 | §4（只给指针） |
| **尚未验证** | 可能已经能用，**但没人验过** | 验一次就能转正 | §5 |

> ⚠ §5 是这份文档里**最容易被忽略、也最该先看**的一节。把"没验过"当成"没有"，会白做一遍工作；
> 把"没验过"当成"有"，会对外承诺一个不存在的能力。

## 3. 能力边界（设计选择，不是缺陷）

这一节的每一条，**改它等于改设计**，不是"补一个功能"。它们的根在 [DESIGN.md](DESIGN.md) §2 ②。

| 边界 | 现状 | 为什么是**有意的** |
| --- | --- | --- |
| **不定积分对非初等函数返回"未实现"** | `∫xˣ dx`、`∫sin(x)/x dx`、`∫e^{−x²}dx` 等 | 它们**确实不是初等函数**。硬给一个式子，用户会拿它去算别的东西 —— 一个错误的原函数比"未实现"危险得多 |
| **部分不定式极限、复变不定积分同理** | 同上 | 同上 |
| **未识别的拓扑空间名报错** | 不返回任何"看起来像答案"的占位串 | 占位串（例如 `π₁(输入)`）是本项目最想避免的形状 |
| **多语言只覆盖一部分** | 导航、顶栏、**14 个学科视图**（415 个模式名 + 184 个参数弹窗字段）已中英双语，可切换并记忆；**页面正文**（设置面板各行、工具/绘图/帮助页、`lib/` 里的提示文案、教程正文）仍是中文 | 覆盖面是**逐步扩大**的，不是"没做"。迁移路径明确：把要翻的那处包一层 `t()` → 往 `src/lib/i18n/en-*.js` 补译文 → `npm run check` 会拦住漏译 |
| **UI 语言与"AI 用什么语言回答"是两件事** | AI 的回答语言由它自己决定 | 不把两者绑在一起 |

## 6. 怎么推翻一条

这份清单**不是**不可动摇的。推翻它的门槛只有一条：**给出证据说明它现在会害人**。

| 类别 | 推翻需要什么 |
| --- | --- |
| 明确不做 | 一个**具体场景** + 证据（用户报障、可复现的失败），证明缺它就不能用 |
| 推迟 | 证明**前置条件已满足**（例如组件包已上传） |
| 能力边界 | 不动门槛 —— 这是设计选择。要改先改 [DESIGN.md](DESIGN.md) §2 ② 与 [DECISIONS.md](DECISIONS.md) |
| 尚未验证 | **验一次**就转正。这条最容易，也最常被跳过 |

**推翻后要做两件事**：① 把条目从本文删掉（不是改成"已完成"—— 见 [AGENTS.md](../AGENTS.md) §5「修完就删」）；
② 如果是"推迟 → 已做"，在 [PROJECT-BOARD.md](PROJECT-BOARD.md) 记一笔。
