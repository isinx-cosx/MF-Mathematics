# AI 助手（阶段 1：对话 + 解释 + 上下文 + 流式）

> 落地于本轮。范围按"第一版只做对话与解释"执行：**工具调用只留契约位置，不执行**；
> 分步显示（§2.2）不在本阶段。密钥、传输、错误分类全在宿主侧，页面只组装消息与渲染。

## 1. 一句话设计

**宿主负责传输与密钥，页面负责组装与渲染；一切计算仍然由 C++ 引擎完成，AI 只解释。**

| 层 | 职责 | 位置 |
| --- | --- | --- |
| 传输 | SSE 分帧、超时、取消、错误分类、增量合并 | `MFMath.Host/AiClient.cs`、`AiSse.cs` |
| 密钥 | DPAPI 加密落盘、只写不读、脱敏视图 | `MFMath.Host/AiDpapi.cs`、`AiBridge.cs`、`AiConfig.cs` |
| 桥面 | `hostObjects.sync.ai`：Info / Configure / SetKey / ClearKey / Test / Start / Cancel / CancelAll / SelfCheck / Busy | `MFMath.Host/AiBridge.cs` |
| 事件 | `ai.started / delta / reasoning / toolcall / usage / notice / done / error / test` 经 PushHub 推给页面 | `MFMath.Host/PushHub.cs` + `src/lib/push.js` |
| 页面 | 消息组装（隐私开关）、token 估算、公式切分渲染、会话落盘 | `src/lib/ai/bridge.js` |
| 界面 | 右侧**非模态抽屉**面板 + 设置 → AI 分组 | `src/components/ai/AiPanel.vue`、`src/components/settings/AiGroup.vue` |

## 2. 三条纪律（照搬 MVS Agent 的模型层，用 C# 落地）

1. **流式是原语**：`AiClient` 只有 `StreamAsync`，阻塞式结果是它的派生。事件里从第一天就
   有 `tool_call_delta`（本版不执行，但契约留位——否则以后加"AI 调度引擎"要重写传输层）。
2. **能力缺失是可观测的降级**：缺 `usage`、流里出现坏 JSON、没有 `[DONE]` —— 都不是崩溃，
   而是 `notice`（`missing_usage` / `bad_sse_data` / `truncated_stream`）。
3. **错误是一等事件**：分类为 `config | network | http | protocol | timeout | aborted`。
   实现在 `AiClient` 的 catch 链里有明确分工——**流吐了一半断掉**是 `IOException` → `network`，
   与"端点回了看不懂的东西"（`protocol`）分开，因为前者重试可能成功、后者不会。

另外两个实测易踩点（都在代码注释里）：
- `usage` 尾包的 `choices` 是**空数组**，必须在取 `choices[0]` 之前处理；
- `tool_calls` 的参数是**按 index 分组的 JSON 碎片**，拼完才可能合法。

## 3. 密钥与隐私

**密钥不进渲染进程**，这是与其它设置最不同的一点：

- 其它设置走"页面写 JSON → `sys.StoreWrite`"，因为页面本来就知道内容；
  AI 配置**不能**这样——它包含 API Key，一这么走密钥就必须先出现在页面里。
- 所以 AI 配置由宿主自己读写 `%LOCALAPPDATA%\MFMath\settings\ai.json`，
  页面对外只有 `hasKey / keySource / keyPersisted` 三个布尔/枚举，**看不到密钥本身**。
- 加密用 Windows DPAPI（`CryptProtectData`，当前用户范围，禁止弹 UI），
  **P/Invoke 而不是拉 NuGet 包**（宿主依赖清单刻意短）。
- **DPAPI 不可用时不降级成明文**：密钥只留内存，界面明说"重启后要重填"。
- 页面就算用 `sys.StoreRead("ai")` 读到整个文件，拿到的也只是密文。

**会发送什么**（设置 → AI → 「会发送什么」逐项可关，默认值就是隐私承诺）：

| 内容 | 默认 | 理由 |
| --- | --- | --- |
| 问题文本 | 必需 | 没有它就没有对话 |
| 当前表达式 | **开** | 不开的话 AI 看不到你在算什么，讲解质量会很差 |
| 引擎结果 | **开** | 且明确告诉模型"以此为准" |
| 会话历史 | 关 | 私人对话内容；打开后按"保留 N 轮"截断（成本闸门） |
| 控制台代码 | 关 | 那是用户的私人代码 |

面板底部实时显示**这一轮将发送约多少 token**与包含哪些部分（与 `buildMessages` 用同一份
逻辑算，不另算一遍），上下文窗口的来源也如实标注（"你声明的值" / "保守默认"）。

## 4. 硬约束：AI 不得成为计算源

系统提示词里写明"所有计算由 C++ 引擎完成，你只做解释"，但**提示词不是机制**。本轮的机制与
断言是：

- AI 的输出**只进面板**，不写任何计算页的结果区（结果区永远显示引擎值）；
- CDP 用例 `cdp-ai.mjs` 里有一条把这条钉住的断言：假端点故意回 `1+1=3`，
  断言计算页 LCD **仍然是 2**（引擎算出来的值）。这条断言存在的意义是：以后谁把 AI 的输出
  接到结果区，它立刻变红。
- 命令/输出**永不执行**：不 `eval`、不拼 HTML。面板里模型正文走插值，公式片段交给
  `MathLatex.vue`（KaTeX 内部安全渲染），切分只认 `$...$` / `$$...$$`。

阶段 2（分步）与阶段 3（工具调用）要在这条红线内做：分步的每一条式子回引擎核验
（`compare_expr`）、核验不过标黄并保留原文；工具调用只允许映射到已注册的引擎 action。

## 5. 验收与证据

| 用例 | 断言 | 结果 |
| --- | --- | --- |
| `cdp-ai.mjs`（新，自带假端点） | 配置读写、**密钥不外泄**（脱敏视图无明文、落盘是密文、password 输入框）、流式增量、停止、**七类异常**（401 / 500 / 坏 SSE / 无 usage / 无 [DONE] / 连接失败 / 超时）、异常后仍可继续、隐私开关真的改变请求体（历史 2 条 vs 14 条）、**AI 不得当计算源**、自检、面板非模态、不可用时诚实提示 | **52 / 0** |
| `cdp-settings.mjs`（更新） | AI 组从占位变真实设置（有可用开关、无待实现标记、逐项隐私开关、密钥状态说明）；「占位必须说清依赖」这条覆盖挪到仍占位的搜索组 | 30 / 0 |
| 全套回归（13 个用例一轮跑完） | — | **408 / 0** |

自检（设置 → AI → 自检，不联网）三项：DPAPI 可用性、**SSE 分帧在 1/2/3/5/17/64 字节
切分下结果一致**、配置目录可写。

## 6. 本地假端点（不联网、不要真 key）

`tests/fake-ai-server.mjs` 跑在真实 TCP + 真实 SSE 上，场景由最后一条 user 消息触发：

| 触发词 | 行为 |
| --- | --- |
| `断开` | 吐两个字后粗暴掐断连接（验证 network / "吐了一半"） |
| `慢速` | 每 300ms 一个字（验证流式渲染与停止） |
| `挂起` | 吐一个字后永不结束（验证超时） |
| `500` / `401` | 对应状态码 + JSON 错误体 |
| `坏JSON` | 中间塞一条不是 JSON 的 data |
| `无usage` / `无DONE` | 触发两种降级通知 |
| `思考` | 先 `reasoning_content` 再正文（DeepSeek 式思维链） |
| `公式` | 正文带回 `$...$` 与 `$$...$$` |

外加给测试用的 `GET /__requests`（**记录请求原文**，隐私断言靠它）、`POST /__reset`、
`GET /__health`。密钥只记"有没有 + 末四位"，假端点也不持有全文。

## 7. 与 v1 的差异（有意为之）

| v1 | 现在 | 为什么 |
| --- | --- | --- |
| 12 项设置（provider / model_map / localModel / cache…） | **10 项** | provider 不做注册表 → 就是三个预设按钮；`model_map`（"Sonnet"→真实模型名）是内部间接层，用户不需要知道；localModel 由 Ollama 预设覆盖；cache → 会话记录（对话缓存会让回答过期） |
| 模态对话框 | **非模态右侧抽屉** | 用户要一边看结果一边问；也符合"不弹窗口"的一贯要求 |
| `agent.py` 正则从正文抠 JSON 当工具调用 + Python `eval()` | **不做**（契约留位） | 原生 `tool_calls` 按 index 累积才是正解；`eval` 永不引入 |
| 有 key 就绕过配额、`balance` 只做显示 | **BYO Key：不登录、不配额** | v1 的本地计数是假的，站点也没有对账语义；把 AI 与用户系统耦合成一次大工程不划算 |
| 分步是一整块只读富文本 | 阶段 2 再做（引擎出结构 + AI 出措辞 + 每步核验） | 见 §2.2 与 §0.4 第 4 条决策 |

## 8. 已知边界

- **上下文窗口多数探不到**：OpenAI / DeepSeek 的兼容层不返回上下文长度，所以默认按 32k
  保守估计并**如实标注来源**；`usage.prompt_tokens` 只用来显示本轮消耗，尚未做估算自校准
  （阶段 2 可加，MVS Agent 的做法是单次比值钳在 `[0.4, 3]` 后走指数滑动平均）。
- **会话落盘只落最终消息**（`ai-chat.json`，最多 40 条），不落增量——日志里允许有冗余，
  不允许有歧义；被截断的中间过程不在日志里。
- **工具调用未实现**：事件已经发出来但页面忽略它，界面里也没有"AI 执行了什么"的卡片。
- **没有 markdown 渲染**：正文按纯文本 + 公式片段渲染（模型输出是不可信输入，
  少一个渲染器就少一片注入面）。要加就得走"构造 DOM 节点/受控渲染器"，绝不拼 HTML。
- **超时是整轮墙钟上限**（默认 120s），没有"首字节超时"与重试退避。
