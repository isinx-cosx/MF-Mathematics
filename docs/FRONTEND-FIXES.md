## 2. 顺手修掉的同类问题（报告未提）

- **`isSkippedField` 过宽**：`includes("函数")` 会把**真的要喂给引擎**的「第二个函数」（内积空间的 `g`）、「未知函数」（一阶 ODE 的 `yvar`）一并跳过。实测 `buildEngineArgs("一阶ODE","y")` 原本给出 `{f, var}` 而缺 `yvar`。现在只认显式约定（`（输入框）`）与明确属于主表达式的措辞（表达式/被积/通项/变量）。
- **`exportImage` 的措辞**：注释与按钮写"2 倍分辨率"，实际是 `drawImage` 把**已渲染位图放大**到 2 倍尺寸——像素数是 2×、细节不是。注释与六个页面的按钮 title 都改成"2 倍像素"。
- **过期文案**：`pendingInput.js` 里「设置面板尚未实现（方案 P1）」，面板早已实现。现在指向 `/settings?group=ai`（示例是"配置 DeepSeek API"），并删掉 `check-examples.mjs` 里对应的过时例外条目。
- **`cdp-engine-coverage.mjs` 一直没登记进 `run-all.ps1`**（49 个 `.mjs` 里 41 个已登记）→ 已登记。
- **构建期自检新增一项**：`check-ui.mjs` 现在检查 `engineMap.js` / `engineMapExtra.js` 里的**重复键**（JS 后者胜，前面的是"改了没反应"的死条目）。

## 4. 这次新暴露的既有缺陷（20 处，已登记为"已知失败基线"）

`cdp-engine-coverage` 是"每个视图 × 每个模式都点一遍计算"的用例，**此前从未跑过**。
它第一次跑就报了 20 处失败——都不是本次改动引入的，我已按原因分成三类写进用例的
`KNOWN_FAIL`（并让用例在"修好了却忘了删条目"时报错）：

1. **关键词字段被当表达式归一化**（7 处：Cauchy积分 / 围道积分 / 复数运算 / 数值求导 /
   最优步长 / p值 / 乘积测度）。机制：主输入框是 MathLive，emit 时把整串（含 `;` 后的
   关键词段）交给引擎的 `to_engine_expr`，而它会把未知多字母标识符拆成变量乘积
   （`central → c*e*n*t*r*a*l`，实测）。**走多参数弹窗（纯 `<input>`）不受影响**，
   所以这些模式的弹窗路径是好的，只有"`;` 便利路径"走不通。
   注：引擎的归一化本身是**保语义**的（`1/2x → 1/(2*x)`，与 raw 同值 0.125，实测），
   所以这不是引擎算错，而是"单词不该走表达式通道"。
2. **算完不弹结果对话框**（9 处：拓扑 7 个模式 + 测度论 2 个）——界面缺口。
3. **模式自身的参数/期望问题**（4 处：条件期望缺数组参数、全概率公式与贝叶斯公式的概率表
   没解析出 `P(B|A1)`、单侧极限的默认示例是左 −∞/右 +∞ 而引擎如实报"不存在"）。

这三类我没有在这次一起改：前两类是"接线/界面"决策（要不要支持 `;` 里写关键词、要不要给这些
模式补结果窗），第三类要动各自的参数构造，都不在本次审查清单内，且改错会影响面更大。
要修的话建议单独立项。

### 4.1 一个顺序坑（我登记这个用例时踩到的）

`cdp-engine-coverage` 会**走遍每个视图并逐个模式点一次计算**，因此会顺带把控制台编辑器内核
加载进来、在绘图页留下采样与点。我一开始把它登记在用例列表**中间**，结果后面三条断言要
"干净初始状态"的用例集体变红：`cdp-tutorials-keypad` 43/3、`cdp-plot-verify` 3 处失败、
`cdp-console` 63/3。把这三条单独跑在干净宿主上分别是 **46/0、9/0、66/0** —— 也就是说
失败全部来自顺序污染，不是功能回归。现在它被放在 `run-all.ps1` 的**最后**，并写明了原因。
